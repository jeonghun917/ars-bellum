# 100 대 100 측정 (M2_SPEC 11.2)

통과 기준은 없고, 병목을 숨기지 않고 적는다. 측정 빌드: `ccr-3692cb93-6pjzuu-scale` (70eb5a4, 135d372).

## 시뮬레이션 (`tools/m2_scale_bench.mjs`, 그리지 않고 계산만)

틱 예산 50 ms(초당 20틱). 3장면(정면 충돌, 작전, 패주) × 3회 × 60초.

| | 중간값 | 상위 5% | 예산 초과 틱 |
|---|---|---|---|
| 20 대 20 | 1.2–2.0 ms | 1.7–4.1 ms | 0 |
| 100 대 100 | 13.8–18.6 ms | 19.7–32.4 ms | 1200틱 중 0–4 |

100 대 100에서 시간이 드는 곳: 몸 부딪힘 계산 약 46%, 사기(측면 판정이 병사 수의 제곱) 약 25%, 전투 대상 찾기 약 21%.
→ 예산 안. 다만 휴대폰 CPU는 이 서버보다 느리므로, 몸 부딪힘과 사기 측면 판정이 먼저 줄일 곳.

자료: `sim-100v100.json`, `sim-20v20.json`.

## 그리기 (`tools/m2_scale_render.mjs`)

이 서버에는 그래픽 장치가 없어 소프트웨어로 그렸다(SwiftShader). 숫자는 비용이 어디 있는지만 보여 준다.
100 대 100: 그리기 호출 약 690–790회, 삼각형 80만–118만 개, 초당 1.1–1.7장면, 메모리 124–136 MB, 틱 누락 0.
9회 중 4회만 끝남(하청 세션의 실행이 중간에 끊김), 20 대 20 그리기 측정은 못 함. 다시 돌리지 않음: 아래 휴대폰 결과가 답.
→ 그리기 호출이 병사 수에 비례해 늘어난다(병사마다 따로 그림). 묶어 그리기(인스턴싱)가 줄일 곳.

자료: `render-100v100-partial.json`.

## 휴대폰 (사용자 직접, 2026-11-01)

`?scale=100&debug`로 열어 봄: "렉 처음 로딩만 걸리고 쾌적함." 초당 장면 수는 기록하지 않음.
→ 처음 불러올 때 멈춤(모델과 그림 준비)과 조작 불편(6번 단계에서)이 남은 일.

자료: `owner-phone.json`.

## 판정 제안

- 20 대 20: 휴대폰에서 쾌적(사용자 확인). 시뮬레이션은 예산의 4% 정도.
- 100 대 100: 휴대폰에서 쾌적(사용자 확인). 시뮬레이션은 예산의 30–65%.
- 나중에 손볼 곳(급하지 않음): 첫 로딩 멈춤, 몸 부딪힘·사기 측면 판정 계산, 병사 묶어 그리기.
